# page-test-case-writer

帮用户写 **pageqa** 的测试用例 Markdown 文件。用例就是「自然语言测试脚本」：agent 把每个步骤（非空行）解析成浏览器操作（`navigate` / `snapshot` / `click` / `fill` / `select_option` / `pick_date` / `hover` / `upload` / `download` / `scroll` / `press` / `wait` / `wait_for` / `assert_text`），跑通后默认固化成零模型回放脚本。

## 何时使用

- 「写测试用例」「生成测试脚本」「整理页面测试 .md」「给页面测试 agent 加用例」
- 给一段自然语言，想转成能直接跑的用例文件
- 问「用例怎么写」「格式是什么」「为什么报断言数不足 / 步骤未跑满」

## 三条硬规则（不遵守一定跑错）

### 1. `## 场景名` 分隔场景；`#` 与 `>` 是注释

- `## 场景名` 起一个新场景，到下一个 `## ` 为止。每个场景是独立运行单元：**独立的子进程、bsk session 与浏览器窗口**。
- `#` 一级标题与 `>` 引用行是注释：**既不算步骤，也不算断言行**。开场说明、前置条件（要不要先登录）、背景、理由，全部写成 `#`/`>`。
- `## ` 之前的所有文字会被整体丢弃（含开场说明）；文件里一个 `## ` 都没有时，整份文件当作单个场景。
- 提示：把「前置条件/为什么这么写」放进 `>` 行，既让人读懂，也不会污染步骤数与断言数。

### 2. 一个非空行 = 一个步骤

pageqa 把每个非空行编号成 `### 步骤 k：<原文>` 交给模型。因此：

- **一行写完一件事**。把一件事拆成多行会凭空多出步骤（模型会照着跑「第 5 步」）。
- 场景内的普通文字行**会被当成步骤执行**。解释性文字必须写成 `>` 行，否则模型会去「执行」那句解释。
- `#`/`>` 行不参与编号，因此步骤总数与行数不一致时，问题一定出在这两类行上。

### 3. 一条「断言」= 一次断言工具调用

- 报告会核对「用例里出现『断言』的行数」与「实际产生的断言结果数」，**必须相等**，少了判 FAIL（`断言数不足`）。
- 一条 `assert_text` 产一条结果；**`download` 本身也算一条断言**。
- 只统计真正的断言句：「断言」后紧跟 `失败 / 未通过 / 未成立 / 不成立 / 结果 / 的 / 写法 / 类型 / 覆盖 / 次数 / 用于` 的叙述用法不计入（「断言失败时记录日志」这类说明不会虚增）。
- **不要加戏**：用例没写的要求不要写成断言行，一条断言只对应一次工具调用。

## 操作句怎么写

用中文动词描述意图即可，agent 会映射到工具；只有「必须走特定工具」的步骤才需要点名工具（下载、上传、回车提交最容易走偏）。

| 意图 | 写法示例 |
|------|----------|
| 打开页面 | `打开 https://example.com`（URL 必须完整含 http/https） |
| 看清页面 | `读取页面内容` |
| 点击 | `点击「提交」按钮` / `点击页面上的「Learn more」链接` |
| 文本输入 | `在「姓名」输入框填写 张三` |
| 下拉选择 | `在「城市」下拉框中选择 北京`（下拉**不是**文本框，别写「填入」） |
| 日期选择 | `在「开始日期」选择 2026-03-01`；范围控件写 `选择 2026-03-01 到 2026-03-31`（只给一端会被工具当场拒绝） |
| 上传文件 | `点击「选择文件」并上传本地文件 D:\data\a.xlsx`（绝对路径） |
| 下载 / 导出 | `点击「导出」按钮并捕获下载的文件；文件名以 .xlsx 结尾` |
| 键盘 | `在「搜索」输入框按回车提交` / `按 Escape 关闭弹窗` |
| 悬停触发菜单 | `悬停「更多操作」，等到菜单出现` |
| 等页面变化 | `等到页面出现「共 12 条」` / `等到 loading 遮罩消失` |
| 等页面之外的事 | `等待 3 秒，等服务端生成导出文件`（**只**用于页面之外的等待） |

下载注意：把**触发下载的那个元素**交给 download，它自己接住这次下载；不要在它前面写一次点击再等下载——点击引发的下载会流走，随后必然报「没捕获到下载」。需要先点确认弹框时，确认按钮才是触发元素（如「在确认弹框中点击『确定』并捕获下载的文件」）。

## 断言句怎么写

- 正向：`断言标题包含 Example`、`断言页面出现「保存成功」`。
- 反向：`断言页面不包含 THIS_TEXT_SHOULD_NOT_EXIST`（工具以 `absent=true` 执行，文本确实不在页面上时**成立**）。
- **选词决定用例有没有价值**：挑只在目标页面/目标区域出现的文本（表格表头、字段 label、成功提示的准确文案）。用「左侧菜单里就有」「页面标题里有」的词，会在页面点偏之后依然「成立」，把一次跑偏判成通过。
- **刻意制造的失败用例**：写一条**正向**断言去断言一个确定不存在的文本（`断言页面包含 THIS_TEXT_SHOULD_NOT_EXIST_XYZ`），并在场景名或 `>` 行注明「预期 FAIL」——用来验证失败报告与退出码 1。别把 `断言页面不包含 X` 当失败用例：它成立时是 PASS。
- **下载的文件名要求**用描述带出来（`…；文件名以 .txt 结尾`），它会被写进 download 的 `expectName`。**不要**再单写一行「断言文件名以 .txt 结尾」——那会让期望断言数多一条，收尾报「断言数不足」的假失败。

## 稳定性：让回放也能过

用例写成的条件会被原样录进回放脚本，因此「等一下」的写法直接决定回放能不能过。

- **进入新页面后、以及任何会改变页面的操作之后，写条件等待**：`等到页面出现「<接下来要操作的那个区域里的地标>」`。不要写「等待 2 秒」——秒数会被回放照付，而条件等待在回放时条件一成立就继续。
- 地标要**真的印在页面上**：表头、按钮文案、字段 label。`aria-label` / `placeholder` / `title` 是快照里的名字、页面上找不到，拿它当文本条件会一直等到超时（这类元素用 CSS 选择器定位）。
- **不要写 `@e3` 这类快照编号**：它只在产生它的那一次快照里有效，下一个动作就失效，回放更是无从谈起。定位一律用可见文本（`点击「Learn more」`）或 CSS 选择器（`在 #search-input 输入 x`）。
- 页面结构不确定时，先写 `读取页面内容` 让 agent 自己定位，再写交互。
- 场景之间**不要互相依赖副作用**（各自独立 session/窗口）；就是「创建 → 编辑 → 删除」这类有隐含顺序的流程，也默认串行跑（并发等于声明这些场景互不依赖）。

## 运行时占位符

名称类字段写死时间戳会反复撞名，用占位符（读取脚本时按本机时间展开一次）：

| 占位符 | 展开为 |
| --- | --- |
| `${timestamp}` | `yyyyMMddHHmm` |
| `${date}` / `${time}` | `yyyyMMdd` / `HHmmss` |
| `${datetime}` | `yyyyMMddHHmmss` |
| `${timestamp:<格式>}` | 自定义，支持 `yyyy yy MM dd HH mm ss SSS` |

例：`在「产品名称」输入框填写 自动化测试产品${timestamp}`。未识别的占位符（如 `${PATH}`）原样保留。

## 模板

单场景（可直接内联给 CLI，也可以存成 .md）：

```markdown
打开 <URL>
断言标题包含 <关键字>
```

多场景套件：

```markdown
# <套件名>（说明，被忽略）

> 前置：<环境/登录态要求，被忽略>

## <场景1 名>
打开 <URL>
读取页面内容
等到页面出现「<目标区域的地标>」
<操作步骤，一行一件事>
断言 <期望>

## <场景2 名>
打开 <URL>
<操作步骤>
断言 <期望>
```

## 生成后自检

- [ ] 每个测试意图都在某个 `## 场景名` **之下**（不在 `#` 或 `## ` 之前的说明里）
- [ ] 一个非空行只做一件事；解释/理由/前置都写成 `>` 行
- [ ] 每个含「断言」的行都能被一次工具调用落成结果；下载没有再单写一行「断言文件名…」；没有用例之外的额外断言
- [ ] 断言用的是**只在目标区域出现**的文本
- [ ] 进入新页面/页面变化后是条件等待（`等到…出现`），没有为页面内的等待写死秒数
- [ ] 没有 `@eN` 编号；URL 完整（含 http/https）；上传路径是绝对路径
- [ ] 多场景之间互相独立（不依赖别场景的副作用）

## 运行与回放

```bash
pageqa examples/mycases.md                      # 整套跑（文本报告）
pageqa --json examples/mycases.md               # JSON 报告（stdout 只有报告）
pageqa --only 2 examples/mycases.md             # 只跑第 2 个场景（边写边调最快）
pageqa --only "表单填写测试" examples/mycases.md  # 按标题精确选中
pageqa --concurrency 4 examples/mycases.md      # 场景互不依赖时才用（上限 8）
pageqa --emit-script examples/mycases.md        # 显式固化回放脚本（默认已开）
pageqa --replay examples/mycases.replay.json    # 零模型回归重跑
```

退出码：`0` 全部断言通过；`1` 任一失败/报错/无法执行（可直接作 CI 门槛）。整体结论看报告末行，逐场景明细与失败卡点（卡在第几步 + 下一步原文）在报告正文里。终端里直接跑（TTY）会进交互模式，可边跑边追加场景并写回落点文件；非交互或加 `--no-tui` 即批处理。
