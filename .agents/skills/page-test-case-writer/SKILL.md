# page-test-case-writer

帮用户写 **pageqa** 的测试用例 Markdown 文件。用例就是「自然语言测试脚本」：agent 把每个步骤（非空行）解析成浏览器操作（`navigate` / `snapshot` / `click` / `fill` / `select_option` / `pick_date` / `hover` / `upload` / `download` / `scroll` / `press` / `wait` / `wait_for` / `assert_text`），跑过的步骤默认会录成零模型回放脚本。

## 何时使用

- 「写测试用例」「生成测试脚本」「整理页面测试 .md」「给页面测试 agent 加用例」
- 给一段自然语言，想转成能直接跑的用例文件
- 问「用例怎么写」「格式是什么」「为什么报断言数不足 / 步骤未跑满」

## 三条硬规则（不遵守一定跑错）

### 1. `## 场景名` 分隔场景；`#` 与 `>` 是注释

- `## 场景名` 起一个新场景，到下一个 `## ` 为止。每个场景是独立运行单元：**独立的子进程、bsk session 与浏览器窗口**。场景名别重复（lint `duplicateScenario`，error）；`## 场景` 下只有空行或注释，运行时会把整个场景静默丢掉（lint `emptyScenario`，error）。
- `#` 一级标题与 `>` 引用行是注释：**既不算步骤，也不算断言行**。开场说明、前置条件（要不要先登录）、背景、理由，全部写成 `#`/`>`。
- `## ` 之前的所有文字会被整体丢弃（含开场说明）；文件里一个 `## ` 都没有时，整份文件当作单个场景。lint 把这类行报成 `preambleText`（warn）：不拦，但确实一个字都没进模型视野。
- 提示：把「前置条件/为什么这么写」放进 `>` 行，既让人读懂，也不会污染步骤数与断言数。

### 2. 一个非空行 = 一个步骤

pageqa 把每个非空行编号成 `### 步骤 k：<原文>` 交给模型。因此：

- **一行写完一件事**。把一件事拆成多行会凭空多出步骤（模型会照着跑「第 5 步」）。
- 场景内的普通文字行**会被当成步骤执行**。解释性文字必须写成 `>` 行，否则模型会去「执行」那句解释。lint 的 `proseStep`（warn）只认两种确定性信号——**句中没有动作动词**的前提下，以句号结尾，或以「说明：/注意：/备注：」开头；它不报，也不代表这行就不是说明。
- `#`/`>` 行不参与编号，因此步骤总数与行数不一致时，问题一定出在这两类行上。

### 3. 一条「断言」= 一次断言工具调用

- 报告会核对「用例里出现『断言』的行数」与「实际产生的断言结果数」，**必须相等**，少了判 FAIL（`断言数不足`）。
- 一条 `assert_text` 产一条结果；**`download` 本身也算一条断言**。
- 只统计真正的断言句：「断言」后紧跟 `失败 / 未通过 / 未成立 / 不成立 / 结果 / 的 / 写法 / 类型 / 覆盖 / 次数 / 用于` 的叙述用法不计入（「断言失败时记录日志」这类说明不会虚增）。
- **不要加戏**：用例没写的要求不要写成断言行，一条断言只对应一次工具调用。
- 一个场景既没有断言行、也没有下载捕获时，lint 报 `noAssertion`（warn）：跑完没有判定依据，结论只能靠文本关键字猜。

## 操作句怎么写

用中文动词描述意图即可，agent 会映射到工具；只有「必须走特定工具」的步骤才需要点名工具（下载、上传、回车提交最容易走偏）。

| 意图 | 写法示例 |
|------|----------|
| 打开页面 | Web 写 `打开 https://example.com`（完整含 http/https）；小程序写 `打开 mp://pages/index/index`（先在交互模式里 `/driver` 切到微信小程序） |
| 看清页面 | `读取页面内容` |
| 点击 | `点击「提交」按钮` / `点击页面上的「Learn more」链接` |
| 文本输入 | `在「姓名」输入框填写 张三` |
| 下拉选择 | `在「城市」下拉框中选择 北京`（下拉**不是**文本框，别写「填入」） |
| 日期选择 | `在「开始日期」选择 2026-03-01`；范围控件写 `选择 2026-03-01 到 2026-03-31`（只给一端会被工具当场拒绝） |
| 上传文件 | `点击「选择文件」并上传本地文件 D:\data\a.xlsx`（绝对路径） |
| 下载 / 导出 | `点击「导出」按钮并捕获下载的文件；文件名以 .xlsx 结尾` |
| 键盘 | `在「搜索」输入框按回车提交` / `按 Escape 关闭弹窗` |
| 悬停触发菜单 | `悬停「更多操作」，等到菜单出现` |
| 等页面变化 | `等到页面出现「共 12 条」` / `等到 loading 遮罩消失` |
| 等页面之外的事 | `等待 3 秒，等服务端生成导出文件`（**只**用于页面之外的等待） |

下载注意：把**触发下载的那个元素**交给 download，它自己接住这次下载；不要在它前面写一次点击再等下载——点击引发的下载会流走，随后必然报「没捕获到下载」。需要先点确认弹框时，确认按钮才是触发元素（如「在确认弹框中点击『确定』并捕获下载的文件」）。

## 断言句怎么写

- 正向：`断言标题包含 Example`、`断言页面出现「保存成功」`。
- 反向：`断言页面不包含 THIS_TEXT_SHOULD_NOT_EXIST`（工具以 `absent=true` 执行，文本确实不在页面上时**成立**）。
- **选词决定用例有没有价值**：挑只在目标页面/目标区域出现的文本（表格表头、字段 label、成功提示的准确文案）。用「左侧菜单里就有」「页面标题里有」的词，会在页面点偏之后依然「成立」，把一次跑偏判成通过。lint 的 `vagueAssertion`（warn）只查「有没有锚点」：断言句要么带引号/「」/反引号，要么写成「包含|出现 X」且 X 不是「数据行/条数/记录/内容/弹框/状态/提示信息」这类泛名词（控制台/网络/状态码这类工具型断言豁免）。它不判断你选的词有没有区分度。
- **刻意制造的失败用例**：写一条**正向**断言去断言一个确定不存在的文本（`断言页面包含 THIS_TEXT_SHOULD_NOT_EXIST_XYZ`），并在场景名或 `>` 行注明「预期 FAIL」——用来验证失败报告与退出码 1。别把 `断言页面不包含 X` 当失败用例：它成立时是 PASS。
- **下载的文件名要求**用描述带出来（`…；文件名以 .txt 结尾`），它会被写进 download 的 `expectName`。**不要**再单写一行「断言文件名以 .txt 结尾」——那会让期望断言数多一条，收尾报「断言数不足」的假失败。lint 的 `downloadExtraAssert`（warn）会点名这种行。

## 稳定性：让回放也能过

用例写成的等待条件会被原样录进回放脚本，因此「等一下」的写法直接决定回放能不能过。脚本只是那一次运行的快照，**改了用例不会自动同步**（见「运行与回放」）。

- **进入新页面后、以及任何会改变页面的操作之后，写条件等待**：`等到页面出现「<接下来要操作的那个区域里的地标>」`。不要写「等待 2 秒」——秒数会被回放照付，而条件等待在回放时条件一成立就继续。即使确实是在等页面之外的事（服务端生成文件），lint 也会报 `hardWait`（warn）——它只让你确认这个秒数非等不可，不拦执行。
- 地标要**真的印在页面上**：表头、按钮文案、字段 label。`aria-label` / `placeholder` / `title` 是快照里的名字、页面上找不到，拿它当文本条件会一直等到超时（这类元素用 CSS 选择器定位）。
- **不要写 `@e3` 这类快照编号**：它只在产生它的那一次快照里有效，下一个动作就失效，回放更是无从谈起。定位一律用可见文本（`点击「Learn more」`）或 CSS 选择器（`在 #search-input 输入 x`）。
- 页面结构不确定时，先写 `读取页面内容` 让 agent 自己定位，再写交互。
- 场景之间**不要互相依赖副作用**（各自独立 session/窗口）；就是「创建 → 编辑 → 删除」这类有隐含顺序的流程，也默认逐个跑。并发量在交互模式的 `/setting` 里调（1/2/3/4/6/8），调高等于声明这些场景互不依赖。

## 运行时占位符

名称类字段写死时间戳会反复撞名，用占位符（**运行时**按本机时间展开一次，同一条用例里多处同名占位符当次取值一致）：

| 占位符 | 展开为 |
| --- | --- |
| `${timestamp}` | `yyyyMMddHHmm` |
| `${date}` / `${time}` | `yyyyMMdd` / `HHmmss` |
| `${datetime}` | `yyyyMMddHHmmss` |
| `${timestamp:<格式>}` | 自定义，支持 `yyyy yy MM dd HH mm ss SSS` |

例：`在「产品名称」输入框填写 自动化测试产品${timestamp}`。录制进回放脚本时仍保持 `${...}` 形式，回放时按当次时间重新展开——所以这类用例回放也不会撞名。

名字只有 `timestamp` / `date` / `time` / `datetime` 四个（`${timestamp:<格式>}` 也算合法）。别自己造 `${PATH}` 这种：运行时它会被原样当字面文本打进输入框，lint 直接报 `unknownPlaceholder`（error）。

## 模板

单场景（可直接敲进交互模式输入框，也可以存成 .md 用 `/run` 加载）：

```markdown
打开 <URL>
断言标题包含 <关键字>
```

模板里的 `<...>` 是占位符，必须整体换成真实值，否则 lint 会当场报出来：`<URL>` 不写成完整的 `https://…`（小程序 `mp://…`）报 `urlScheme`（error）——它只认协议头，认不出「这里还没填」；`断言 <期望>` 不换成页面上真实印着的文本报 `vagueAssertion`（warn）——断言工具只做字面包含，也同样认不出占位符。

多场景套件：

```markdown
# <套件名>（说明，被忽略）

> 前置：<环境/登录态要求，被忽略>

## <场景1 名>
打开 <URL>
读取页面内容
等到页面出现「<目标区域的地标>」
<操作步骤，一行一件事>
断言 <期望>

## <场景2 名>
打开 <URL>
<操作步骤>
断言 <期望>
```

## 生成后自检

- [ ] 每个测试意图都在某个 `## 场景名` **之下**（不在 `#` 或 `## ` 之前的说明里）
- [ ] 一个非空行只做一件事；解释/理由/前置都写成 `>` 行
- [ ] 每个含「断言」的行都能被一次工具调用落成结果；下载没有再单写一行「断言文件名…」；没有用例之外的额外断言
- [ ] 断言用的是**只在目标区域出现**的文本
- [ ] 进入新页面/页面变化后是条件等待（`等到…出现`），没有为页面内的等待写死秒数
- [ ] 没有 `@eN` 编号；Web URL 完整（含 http/https）或小程序用 `mp://`；上传路径是绝对路径
- [ ] 多场景之间互相独立（不依赖别场景的副作用）
- [ ] `pageqa lint <用例文件>` 的 error 为 0（warn 逐条确认过）

## 格式预检：`pageqa lint`

写完或改完用例，先跑这一条：不开浏览器、不调模型，秒级给出「第几行、哪条规则、为什么」。它和运行时共用同一份口径（`src/agent/lint.ts`），所以不会出现「lint 说没事、一跑报断言不足」。

```bash
pageqa lint examples/mycases.md                # 一个或多个用例文件
pageqa lint examples/a.md examples/b.md        # 一次校验一批
pageqa lint --strict examples/mycases.md       # warn 也算失败（接 CI 用这个）
pageqa lint --json examples/mycases.md         # stdout 只有 JSON，便于机读
```

给目录会直接报错（`lint` 只接受用例文件，要逐个给）。退出码：error 为 0 才通过；加 `--strict` 则 warn 也必须为 0。交互模式里每次 `/run` 前也会自动预检一次（只打印前 5 条 + 提示），**刻意不拦**——能跑起来的用例就该让它跑完，要设门槛就用 `pageqa lint`。

规则分两级：`error` 会让用例跑错或跑不动，`warn` 只是写法不统一。共 13 条：

| 规则 | 级别 | 什么时候报 |
| --- | --- | --- |
| `preambleText` | warn | 第一个 `##` 之前有正文（运行时整体丢弃） |
| `emptyScenario` | error | 场景下只有空行/注释（运行时静默丢弃） |
| `duplicateScenario` | error | 场景标题重名 |
| `snapshotRef` | error | 出现 `@e3` 这类快照编号 |
| `urlScheme` | error | `打开/访问/前往/跳转到/进入` 后面的地址不是 `http(s)://` 或 `mp://` |
| `unknownPlaceholder` | error | `${PATH}` 这类未知占位符 |
| `uploadPath` | error | `上传文件` 后面没紧跟绝对路径（相对路径在 bsk 侧解析失败） |
| `hardWait` | warn | 行首 `等待 3 秒`（页面内的等待该改条件等待） |
| `selectAsFill` | warn | 同一行既有「下拉」又有「填写/填入」 |
| `downloadExtraAssert` | warn | 单写一行「断言文件名/已下载…」，让期望断言数多一条 |
| `vagueAssertion` | warn | 断言没有引号锚点、「包含 X」的 X 是泛泛的状态名词 |
| `proseStep` | warn | 无动作动词且以句号结尾，或以「说明：」开头 |
| `noAssertion` | warn | 场景没有断言行也没有下载捕获 |

lint 只认确定性的正则可以命中的特征，宁可漏报也不误报——**它不报不等于写法合格**。

## 运行与回放

写用例时要同时想着「这段能不能被录下来稳定重放」：每次运行的步骤序列默认会录成**回放脚本**，之后可零模型、秒级重跑，只在用例或页面变了才重新用模型跑一遍。

### 现在只有交互模式这一个执行入口

CLI 不再接受 `pageqa run ...` / `pageqa --replay ...` / `--only` / `--json` / `--concurrency` / `--emit-script` / `--no-tui` 等命令行执行参数，带上它们会直接报「已收进交互模式」。原因是命令行直接执行会绕过界面里的格式预检、产物开关、并发口径与驱动选择，两套入口迟早打架（`src/index.ts` 1306 行）。命令行只负责启动界面，以及不跑用例的子命令：

```bash
pageqa                          # TTY 下进入交互模式：唯一执行入口
pageqa --tui                    # 显式写法；非 TTY 下报错
pageqa lint examples/cases.md   # 只做格式静态检查，不跑用例、不连浏览器、不调模型
pageqa sessions                 # 回看历史运行交给模型的参数与全过程
pageqa --help                   # 当前入口的权威清单
```

stdin/stdout 必须都是 TTY；非 TTY（管道 / CI）只打印帮助并退出码 1，跑用例必须在真实终端里。别再找批处理开关。进入界面后：

| 输入 | 作用 |
| --- | --- |
| `/run <路径或关键字>` | 加载用例开跑：精确路径、目录（该目录下全部 `.md`/`.txt`）、文件名关键字都行；多个命中先让模型按文件名挑，挑不出再弹选择器。会切换写回落点 |
| `/replay <脚本.json 或关键字>` | 零模型按录下的步骤重跑；脚本里有几个场景就入队几个，各自计时、各自出报告。不切换落点，可与带模型的场景混在同一批 |
| `/driver` | 切换桌面浏览器 / 微信小程序（小程序用例导航写 `mp://页面路由`） |
| `/setting` | 测试报告(HTML) / 回放脚本 两个独立开关、语言、并发量（1/2/3/4/6/8） |
| `/status` · `/cancel <n>` | 看队列 / 取消还没开始的第 n 个场景 |
| `Esc` · `Ctrl+C` · `/exit` | 中止当前（记为「已取消」，不计退出码、不写回放）/ 收工并打印汇总报告 / 退出 |

`/run` 加载的场景本就在文件里、**不写回**，只切换落点；只有输入框追加的场景才写回，无落点的追加场景退出即丢。

### 回放脚本怎么生成

- 默认开，`/setting` 里可单独关；HTML 报告是另一个开关。除被 `Esc` 取消的场景外，跑过的场景都会录进去（失败运行也录，便于排查「模型这次到底做了什么」）——所以脚本里有某个场景，不代表它当时通过了。
- 按来源分组：一份用例文件 = 一份脚本，`<用例名>.replay.json` 贴着用例放（`examples/smoke.md` → `examples/smoke.replay.json`）。一次会话加载多个用例文件就生成多份，不合并成一份。
- 没有落点的场景（输入框直接敲的内联文本、无用例文件时的追加）不生成脚本。
- 脚本存的是语义定位符（role + name + 同名序号 + 祖先路径），**不存 `@eN`**；`${...}` 占位符按占位符形式存、回放时按当次时间重新展开。

### 改了用例，旧脚本不会跟着改

脚本是那一刻的快照，不与用例文本联动，交互模式的 `/replay` 也不检查源用例哈希：改了措辞、步骤或断言后，旧脚本仍按旧步骤跑。所以**改完用例要重新 `/run` 跑一次带模型的用例刷新脚本，再回放**。回放零模型：断言只做字符串包含（不走语义判断），元素未找到记为「跳过」并继续，其它失败记进报告继续跑完，只有 `navigate` 失败才中止。固定秒数的 `等待 3 秒…` 会被原样照付，条件等待则按条件轮询。回放场景不参与写回、不调用大模型、也不会再生成一份脚本。

### 退出码

退出界面后输出汇总报告，退出码仍按整批报告的结论给：`0` 全部通过；`1` 有场景失败/报错，可直接作 CI 门槛。整体结论看报告末行，逐场景明细与失败卡点（卡在第几步 + 下一步原文）在报告正文里。`Esc` 标成「已取消」不计入退出码；被测缺陷不影响退出码，别用「跑挂了」判断用例写得对不对。
