# 目标

开发一个「页面测试 agent」：用自然语言描述测试意图，agent 自动驱动浏览器打开网页、读取内容、与页面元素交互，并对页面状态进行断言与校验，最终产出可读的测试报告与机器可读结果。

面向持续变化的 Web 页面，让非工程师也能用自然语言编写、运行和维护页面测试，降低端到端 UI 测试的维护成本。

# 范围

- **自然语言驱动**：用 `@earendil-works/pi-agent-core` 状态化 agent 把自然语言测试意图解析为浏览器操作步骤并自动编排执行。
- **浏览器驱动**：用 `browserskill`（`bsk` CLI）连接并驱动一个已运行的真实浏览器（Chrome/Edge），支持公开页与登录态页面。
- **操作能力**：打开网页、读取页面内容（aria 快照/语义观察）、点击、输入/填充、悬停、滚动、等待、断言等。
- **报告**：把 agent 的工具调用序列、断言结论与可读原因整理为文本报告与 JSON 报告，返回可接入 CI 的退出码。
- **LLM 后端**：默认经 CodeBuddy 本地反代（`http://127.0.0.1:3000/v1`，模型 `hunyuan-2.0-instruct`，无需官网 Key）接入混元；可通过配置切换其他 pi-ai provider。

# 非目标

- 移动端原生 App 测试、性能/负载测试、视觉回归（像素比对）。
- 内置被测系统业务知识：页面选择器与断言由 agent 在运行中通过浏览器快照探测。
- CI 平台深度集成（仅产出可接入 CI 的报告与退出码）。
- 自带浏览器下载/管理（复用已安装的 Chrome/Edge + bsk daemon）。

# 验收示例

- A1：给定自然语言意图「打开 https://example.com 并断言标题包含 Example」，agent 驱动浏览器打开页面、读取标题、输出通过报告。
- A2：给定含交互的意图「在搜索框输入 X 并点击搜索，断言结果页出现 X 关键字」，agent 完成填表、点击、等待、断言。
- A3：当元素缺失或断言失败时，agent 输出失败报告并给出可读原因，进程退出码非零。
- A4：运行产出结构化报告（文本与 JSON 两种格式），可被 CI 读取。

# 约束与不变量

- 浏览器操作通过 `bsk` 连接真实浏览器；需先 `bsk session start` 得到 session id（可由 CLI `--session` 指定或自动创建）。
- 自然语言解析依赖 LLM（`pi-agent-core` + `pi-ai`）；默认后端为 CodeBuddy 反代（混元），离线无反代时不可用。
- 失败必须有可读原因（断言期望值、实际值、页面证据），不得静默通过。
- 报告与退出码使工具可被 CI 直接消费。

# 决策

- D1（Q1，原 Playwright→变更）：浏览器驱动改用 **browserskill（`bsk`）**，连接真实浏览器而非自起 Chromium。
- D2（Q2）：运行时仍为 **Node.js + TypeScript**，npm 分发，CLI 入口。
- D3（Q3，原规则解析→变更）：自然语言驱动改用 **`@earendil-works/pi-agent-core`** 状态化 agent（LLM 规划），通过 bsk 工具执行；默认 CodeBuddy 反代（混元）免官网 Key。
- D4（Q4）：交付形态仍为 **CLI 命令行**，输入自然语言或脚本文件，输出报告与退出码。
