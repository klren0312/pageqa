# ADR-0021：命令行退化为「启动器」，执行统一进交互模式

- 状态：已采纳 · 日期：2026-10-23
- 相关：ADR-0005（交互模式是核心用法）、ADR-0013（场景进程隔离）、ADR-0020（小程序驱动后端）

## 背景

pageqa 一直有两套「跑用例」的入口：命令行的 `pageqa run <用例>` / `--replay <脚本>`，以及交互模式里的 `/run` / `/replay`。两套入口共用同一批参数，却各有一半参数只对其中一套有意义（`--only`、`--emit-script`、`--usage-stream` 是父子进程协议；`--json`、`--out`、`--suite` 只对批处理有意义）。结果是：敲错参数时，报错文案与「界面里该点哪里」对不上；「用哪个测试驱动」既是启动参数（`--driver`）又是会话内的事；想在 CI 里跑一次用例，还得走一套界面里根本没有的语义。

## 决策

1. **命令行只负责启动交互模式**：`pageqa`（无参）或 `pageqa --tui` 进界面；用例一律在界面里用 `/run <文件>` 加载、用 `/replay <脚本>` 零模型回放。
2. **原先的命令行执行入口一律判为误用**，并给出明确指引（`err.useTuiOnly`）：`run`、`--replay`、`--prefer-replay`、`--suite`、`--only`、`--session`、`--json`、`--out`、`--emit-script`、`--semantic`、`--fail-fast`、`--settle-waits`、`--locate-timeout`、`--no-side-outputs`、`--quiet-side-outputs`、`--usage-stream`、`--no-lint`、`--concurrency`、`--driver`、`--no-tui`。
3. **驱动后端改为会话内选择**：TUI 新增 `/driver`，在「桌面浏览器 / 微信小程序」之间切换；对**之后排队的场景**生效（已跑起来的不受影响），并写回 `~/.pageqa/config.json` 的 `driver` 字段。
4. **父子进程协议不受影响**：父进程 fork 场景子进程时仍用同一批参数，靠 `PAGEQA_INTERNAL_CHILD=1` 区分「内部子进程」与「用户进程」——用户进程里那些参数被判误用，内部子进程照常解析。协议与解析仍是**同一套代码**（ADR-0013 决策二）。

## 后果

- **好处**：只有一套「怎么跑用例」的语义（界面），参数面前后一致；驱动切换不用重开进程；`--help` 里不再有一半看不懂的开关。
- **代价**：**失去了纯命令行的批处理 / CI 入口**。这是有意接受的取舍：先把「人怎么用」理顺。CI 形态作为后续议题单独立 ADR——那时它会以「明确的子命令 + 明确的机器可读输出」的形态回来，而不是复用界面那套参数。
- `/driver` 与小程序驱动的固定串行策略联动（ADR-0020）：切到小程序后并发上限实际为 1，界面上的「并发量」随之隐藏；切回桌面浏览器即恢复。
