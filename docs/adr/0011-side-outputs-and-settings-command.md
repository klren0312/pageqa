# ADR-0011：旁路产物默认生成，`/setting` 是唯一的开关入口

- 状态：采纳（2026-09）
- 背景：一次运行结束会落两类文件——HTML 测试报告（早已默认生成，`pageqa-report/`）与回放脚本（必须显式 `--emit-script` 才生成）。希望两者都默认生成，并且能在交互界面里改这些偏好；语言切换此前独占一个 `/toggle-language`，也一并收进同一个入口。于是新增 `/setting`：**交互模式里修改持久化偏好的唯一入口**。

## 决策一：测试报告与回放脚本默认生成，默认值不进配置文件

两个开关：`htmlReport`、`replayScript`，**缺失即视为开**。只有用户真的改过某一项时才写进 `~/.pageqa/config.json`（写 `false`，或改回时写 `true`，不删键）。

理由：默认开是这次改动的目的；而把两个从没碰过的布尔值塞进用户配置，会让「配置文件里有什么」变成噪声，也让「将来改默认值」变成一件需要数据迁移的事。

## 决策二：`/setting` 是开关的唯一入口，语言并入

`/setting` 打开一个面板（复用 `/model` 的选择器形态），三项：测试报告（HTML）／回放脚本／语言。↑↓ 选择、回车切换并立即写回、Esc 关闭；面板末行显示配置落点。

语言切换从 `/toggle-language` 迁进来；`/toggle-language` **保留为未文档化别名**（不进 `/help`、不进补全列表），不让老习惯突然失灵。模型切换与凭据**不并入**——它们各有专责命令（`/model`、`/login`、`/logout`），塞在一起会把这个入口变成万能大杂烩。

不加「恢复默认」项：默认就是全开，手工切回来即可；多一项就多一种与「改过才写盘」打架的状态。

## 决策三：开关只作用于旁路产物，显式 CLI 参数永远优先

- `--json`、`--out`、stdout 文本报告**不受开关影响**——用户显式要的输出永远照旧。
- `--emit-script`（含显式路径）**优先于配置**：开关关着也能生成。
- 本次**不加**反向 CLI 参数（`--no-report` 之类）：配置里能关就够了。

理由：这两个开关描述的是「我没主动要求的时候，要不要顺手产出」，不是「谁说了算」。让它去覆盖显式请求，等于让一个配置文件悄悄改掉命令行语义。

## 决策四：回放脚本仍贴「当前打开的用例文件」，没有落点就不生成

有源用例文件时（含 `/run` 加载进来的），脚本写到它旁边（`examples/smoke.md` → `examples/smoke.replay.json`），固定命名、允许覆盖；多来源按来源各写一份（沿用 ADR-0005 决策七的拆分规则）；`--emit-script <path>` 显式给了路径就按它写，这条不变。

**没有落点时（无源启动的追加场景）不再生成**，清单里如实写「未生成（本次场景没有落点文件）」。这是对现有「无落点写 cwd 的 `pageqa.replay.json`」的修改：选定的规则是「写到当前打开的用例文件」，而没有打开的用例文件时，往 cwd 扔一个隐式的 `pageqa.replay.json` 是最容易被忽略的垃圾。

生成时机不变：PASS/FAIL 都写（失败的录制正是用回放复现问题的输入），已取消不写（ADR-0002 决策五），模型一步都没成功的空脚本不落盘。

## 决策五：收尾打一份「本次产物清单」，走 stderr

批处理与交互两条路径在收尾各打一次，覆盖原有的零散行（`HTML 报告已生成: …`、`回放脚本已生成：…`、`下次可零模型回放：…`）：

```text
[pageqa] 本次产物：
[pageqa]   测试报告: pageqa-report/report-20260923-153001.html
[pageqa]   回放脚本: examples/smoke.replay.json
[pageqa]   回放方式: pageqa --replay examples/smoke.replay.json
```

多份脚本逐条列，回放方式退化成 `pageqa --replay <上面任一份脚本路径>`（多份时给不出一条可直接复制的命令）。被开关关掉的项写「未生成（/setting 中已关闭）」，没有可回放动作时写「未生成（本次没有可回放的动作）」——**显式说明原因**，否则「默认开着却没有」会被当成坏了。

清单只走 `info()` / stderr，绝不进 stdout（ADR-0002）；报告里的 `script` 字段保持现状（只在显式给了脚本路径时出现）。写盘失败沿用现有约定：只警告、不改退出码；报告开关关闭时不创建 `pageqa-report/` 目录。

## 未采纳的方案

- **脚本默认落到 `pageqa-report/`**：能一次解决「别往仓库里塞文件」，但选定的规则是「贴当前打开的用例文件」——脚本与用例放在一起才能一起评审。
- **脚本文件名带时间戳**：报告是「那一刻的快照」，带时间戳为了留痕；脚本是之后反复使用的工具，多份带时间戳的脚本只会让人不知道该回放哪一份。
- **默认只写 PASS 的脚本**：失败的录制恰恰是「用回放复现问题」的输入。
- **给 `/setting` 加「恢复默认」项**：见决策二。
- **移除 `/toggle-language`**：老习惯不必打断，降级为别名即可。
- **加 `--no-report` / `--no-emit-script`**：见决策三。
