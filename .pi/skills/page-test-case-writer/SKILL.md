# page-test-case-writer

帮助用户编写 **page-test-agent** 的测试用例 Markdown 文件。agent 用 `pi-agent-core` 把自然语言解析为浏览器操作步骤，并通过 `browserskill`（bsk）连接真实浏览器执行。用例文件就是「自然语言测试脚本」。

## 何时使用

- 用户要「写测试用例」「生成测试脚本」「整理页面测试 .md」「给页面测试 agent 加用例」
- 用户给了一段自然语言想转成可运行的测试文件
- 用户问「用例怎么写」「格式是什么」

## 核心约定（必须遵守，否则 agent 解析错误）

### 1. 场景分隔用二级标题 `## `

- 一个文件可含多个场景，用 `## 场景名` 分隔；每个 `## ` 下是该场景的自然语言步骤。
- **一级标题 `#` 与所有 `## ` 之前的文字（开场说明）会被 agent 忽略，不计入任何场景**——不要把测试意图写在一/开头说明里。
- 文件**没有**任何 `## ` 时，整份文件当作单个场景。

正确：
```markdown
# 页面测试套件（这一行是说明，被忽略）

## A1 打开官网并断言标题
打开 https://example.com
断言标题包含 Example

## A2 搜索并断言结果
打开 https://example.com
点击「Learn more」链接
等待页面加载
断言页面包含 IANA
```

错误（意图写在说明里，不会被运行）：
```markdown
# 打开 example.com 并断言标题包含 Example   <-- 写在 # 下，agent 忽略！
```

### 2. 用自然语言描述操作与断言

agent 内置浏览器工具：`navigate / snapshot / click / fill / hover / scroll / wait / assert_text`。
用中文动词即可，agent 会映射：

| 意图 | 写法示例 |
|------|----------|
| 打开网页 | `打开 https://example.com` / `导航到 https://...` |
| 读取内容 | `读取页面内容` / `查看页面`（agent 自动快照） |
| 点击 | `点击「提交」按钮` / `点击页面上的链接“Learn more”` |
| 输入 | `在搜索框输入 playwright` / `在输入框 #q 填入 hello` |
| 悬停 | `悬停「菜单」` |
| 滚动/等待 | `滚动到「 footer 」` / `等待 2 秒` |
| 断言文本 | `断言标题包含 Example` / `断言页面包含 IANA` / `断言页面出现“登录成功”` |
| 断言不存在（失败用例） | `断言页面包含 THIS_TEXT_NOT_EXIST`（用于验证失败可读报告） |

### 3. 断言句式提示

- agent 从结论里解析「断言「X」：成立/不成立」。你只需在步骤里写清**断言什么**，例如 `断言标题包含 Example`、`断言页面包含 IANA`。
- 一个场景可有多条断言；任一断言失败 → 该场景 FAIL。
- 失败用例（预期不通过）应明确断言一个不存在的文本，用于验证「失败可读原因 + 退出码非零」。

### 4. 元素定位

- 优先用可见文本引用：`点击「Learn more」`、`点击“提交”按钮`。
- 也可用 CSS 选择器或 bsk 快照里的 `@eN` 引用：`点击 @e3`、`在 #search-input 输入 x`。
- 若页面结构不确定，先写 `读取页面内容` 让 agent 自行定位，再写交互。

## 生成模板（直接复用）

单场景：
```markdown
打开 <URL>
断言标题包含 <关键字>
```

多场景套件：
```markdown
# <套件名>（说明，被忽略）

## <场景1 名>
打开 <URL>
<操作步骤>
断言 <期望>

## <场景2 名>
打开 <URL>
<操作步骤>
断言 <期望>
```

## 检查清单（生成后自检）

- [ ] 每个测试意图都在某个 `## 场景名` **之下**（不在 `#` 或开头说明里）
- [ ] 断言用「断言 X 包含/出现/等于 Y」句式，理由明确
- [ ] 失败用例断言的是确定不存在的文本
- [ ] URL 完整（含 http/https）
- [ ] 多场景套件每个场景相对独立（不依赖其他场景的副作用，除非刻意顺序）

## 运行方式（告诉用户）

```bash
# 需先 bsk session start 拿到 session id
node dist/index.js --session <id> 用例文件.md          # 文本报告
node dist/index.js --session <id> 用例文件.md --json    # JSON 报告
# 整体结论 FAIL（任一场景失败）→ 退出码 1；全 PASS → 0
```
